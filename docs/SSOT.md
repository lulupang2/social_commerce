# SummerGear 제품·기술 기준

결정 기준일: 2026-09-18 · Go 전환 상태: 설계 문서 작성, 구현 전

서핑·테니스 개인 중고거래에 입점사 판매를 추가하는 것이 목표입니다. 이 문서는 확정 방향과 현재 구현을 구분하며, 상세 계약은 각 기준 문서로 연결합니다.

## 확정 방향

| 영역          | 기준                                                               |
| ------------- | ------------------------------------------------------------------ |
| 고객 화면     | Next.js 웹앱 + Expo / React Native WebView 유지                    |
| 백엔드        | Go + Fiber로 서비스 API와 거래 규칙 분리                           |
| 인증          | Go에서 네이버·카카오 로그인과 서비스 세션 관리; Supabase Auth 교체 |
| 회원·입점사   | 로그인 회원과 판매 주체 분리, 업체 구성원별 권한 관리              |
| 거래 확장     | 상품·재고·주문·PG 결제·환불·정산을 단계적으로 추가                 |
| 데이터 인프라 | Supabase PostgreSQL 유지; River 작업 큐도 같은 DB 사용             |

이전 기술 결정과 충돌하는 범위는 [ADR 003](adr/003-go-backend-and-social-auth.md)을 우선합니다. 구체적인 API·세션·거래 정책의 초안은 구현 과정에서 계약으로 확정합니다.

배포·서버 테스트는 `nhn-rocky`, DB는 Supabase PostgreSQL 유지, 작업 큐는 River로 확정했습니다. PG는 토스페이먼츠 테스트 환경만 연동합니다. 최종 결정은 [ADR 005](adr/005-supabase-river-toss-test.md)이며 실제 결제·지급은 이번 범위가 아닙니다.

## 현재 구현과의 차이

현재 저장소는 Supabase 이메일 OTP, 브라우저의 Supabase 직접 데이터 접근, RLS와 Realtime을 사용합니다. Go 서버와 자체 세션, 입점사·주문·PG·정산은 이 문서 변경으로 구현되지 않습니다.

기존 문서의 완료·테스트 통과 표시는 이전 작업 기록입니다. 2026-09-18 문서 작업에서는 앱·DB·PG 통합 테스트를 다시 실행하지 않았습니다. 현재 실행 방법은 [개발 가이드](development.md)에 있습니다.

## 제품과 화면 원칙

- 서핑 `surf`, 테니스 `tennis`의 장비 거래·커뮤니티를 유지합니다.
- 서핑은 보드 길이·부력·핀 시스템·웻슈트 두께, 테니스는 헤드 크기·무게·그립·플레이 스타일 등 종목별 스펙을 다룹니다.
- 사용자 화면은 `apps/web`, 기기 연동은 `apps/mobile`, 기존 TypeScript 화면·브릿지 계약은 `packages/domain`에 둡니다.
- 개인 매물·커뮤니티의 검토·공개 상태 전이와 감사 기록을 유지합니다.
- 규칙 기반 추천은 `맞춤 추천` 또는 `추천 이유`로 표기합니다.
- 입점사·플랫폼 운영자 화면의 권한은 서버에서 검증합니다.

## 인증과 데이터 원칙

- 소유권은 서버가 확인한 내부 회원 ID를 기준으로 합니다. 전환 전 기능은 기존 Supabase Auth/RLS를 사용하며, 새 세션이 기존 `auth.uid()`에 자동 연결된다고 가정하지 않습니다.
- 외부 소셜 계정과 내부 회원을 분리하고 이메일 일치만으로 계정을 병합하지 않습니다.
- 공개 데이터는 승인된 범위로 제한하고 이미지 저장소는 private으로 유지합니다. 이미지 접근 권한은 검사 후 제한된 수명의 서명 URL로 제공합니다.
- 이전한 기능은 Go가 쓰기를 소유하고 기존 직접 쓰기 경로를 차단합니다. 남은 인증 의존성을 해소하기 전에는 Supabase Auth를 운영에서 종료하지 않습니다.
- 결제·환불·정산은 서버 금액 검증, 중복 방지, 상태 전이, 감사 기록과 외부 결과 대조를 갖춥니다. 실패를 데모 성공으로 대체하지 않습니다.

## 배포와 테스트

[배포·테스트 환경](deployment.md)에 따라 운영과 테스트 DB·계정·볼륨을 분리합니다. Supabase 백업·복구와 연결 한도를 확인하고, 기존 스키마에 Go 인증·거래 모델을 추가합니다. 운영 DB는 Docker로 이전하지 않습니다.
