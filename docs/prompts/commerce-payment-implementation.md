# 거래·PG 테스트 연동 구현 프롬프트

아래 내용을 다음 구현 작업에 붙여 넣는다. 이 파일 작성 자체는 구현 실행이나 배포 승인이 아니다.
기본 프롬프트는 키 없는 구현·검증까지 요청하며, 실제 PG 연결과 배포는 뒤의 추가 프롬프트로 요청한다.

## 1. 구현과 키 없는 검증

```text
SummerGear에 주문·재고 예약·토스페이먼츠 테스트 결제 기반을 구현해줘.

먼저 AGENTS.md, docs/commerce-payment-work-plan.md, docs/commerce.md,
docs/payment-test-setup.md, docs/authentication.md, docs/adr/005-supabase-river-toss-test.md를 읽어줘.
현재 OpenAPI·domain 계약·migration·API 쿼리와 대조하고 오래된 문서의 완료 표시는 그대로 믿지 마.
git status --short --branch, git worktree list, 최근 커밋을 확인하고 기존 미커밋 변경을 보존해.

첫 범위는 승인된 테스트 판매자 1곳, 주문당 실제 Go 상품 1종·수량 1개,
KRW 정수 금액, 테스트 카드 승인·조회·전체 취소야.
배송 없는 테스트 상품으로 배송비·수수료 0원, 예약 15분을 초기안으로 쓰되
PG 공식 제약과 충돌하면 근거와 변경안을 문서화해.
입점 신청 관리 UI·부분 취소·가상계좌·실제 결제·정산/실지급은 제외해.

다음 순서로 진행해:
1. 실제 데이터 모델을 확인하고 최소 판매 주체·구성원 권한·승인 상태를 구현해.
2. 주문·가격 스냅샷·재고 예약·결제 시도·취소·PG 이벤트를 새 migration으로 추가해.
3. Go API, OpenAPI, 웹 런타임 검증과 오류 계약을 함께 구현해.
4. PG 어댑터를 만들고 가짜 PG로 승인·조회·취소·웹훅과 장애 복구를 검증해.
5. River로 예약 만료와 불명확한 결제 결과의 대조·재시도를 구현해.
6. 상품 상세→주문서→결제창→승인 확인→주문 상세 및 전체 취소 화면을 연결해.

현재 공용 임시 계정은 주문 권한 검증에 사용하지 마.
독립된 구매자 A/B·판매자 A/B 인증 fixture로 권한을 검증하고,
공개적으로 임의 회원 ID를 지정하는 로그인 기능은 만들지 마.
데모·브라우저 로컬 상품을 실제 주문에 섞지 마.
가격·회원·판매자 권한은 서버에서 검증하고 중복 주문·승인·취소는 멱등성과 DB 제약으로 막아.
PG timeout이나 성공 후 DB 실패는 결과 불명 상태로 저장해서 대조하고,
성공 페이지 도착이나 가짜 fallback을 결제 완료로 처리하지 마.
웹훅은 이벤트별 공식 검증 방법을 확인하고 중복·역순·위조 입력을 검증해.

기존 TOSS_* 예시 변수는 아직 소비되지 않을 수 있으므로 코드와 대조해 설정을 연결해.
PAYMENT_MODE=test와 DB test 가드를 유지하고 live 키는 거부해.
키가 없어도 가능한 구현·가짜 PG·격리 DB 검증은 끝내줘.
시크릿을 채팅·Git·로그·이미지·브라우저 설정에 넣지 마.

웹 타입 검사·테스트·lint·build를 실행해.
Go 검증은 Linux에서 수행하고 전체 unit/vet, integration 컴파일과 실제 격리 DB 검사를 구분해.
새 테스트가 실제 CI/DB 실행 경로에 포함되게 해.
nhn-rocky를 사용한다면 기존 서비스와 미커밋 원격 저장소를 보존하고,
작은 서버에서 빌드·DB 검사를 병렬 실행하지 마.

이번 요청은 구현과 격리 검증까지야. 공개 사이트 교체·실제 PG 키 연결·원격 push는 하지 마.
별도 요청 없이는 새 에이전트나 다른 작업을 만들지 마.
완료 시 변경 파일, 계약/migration/환경변수 영향, 실제 실행 결과,
남은 실제 PG·모바일 검증, 브랜치·커밋·원격 반영 여부를 보고해.
진행 결과는 docs/commerce-payment-work-plan.md에서 연결되는 검증 기록으로 남겨줘.
```

## 2. 테스트 키 연결과 테스트 배포

첫 단계 완료 후 실제 준비값을 채워 사용한다. 키 원문은 넣지 않는다.

```text
구현된 거래 기능을 토스페이먼츠 테스트 환경에 연결하고 nhn-rocky 테스트 사이트에 배포해줘.

테스트 도메인: [주소]
배포 대상 경로: [경로]
테스트 전용 DB와 marker: [식별 정보; 접속 비밀번호 제외]
서버 비밀 설정 파일: [접근 제한된 파일 경로; 키 원문 제외]
PG SDK에 맞는 테스트 키 준비 여부: [준비/미준비]
독립 구매자·판매자 계정과 사이트 접근 범위: [준비 상태]

docs/commerce-payment-work-plan.md와 직전 구현 검증 기록부터 확인해.
기존 공용 fixture preview를 준비된 실제 PG 테스트 환경으로 착각하지 마.
배포 전 이미지 ID·현재 migration 상태·백업과 롤백 방법을 기록하고,
migration 성공→API/worker 준비→웹/gateway 연결 순서로 배포해.
기존 다른 서비스와 비밀 설정을 보존하고 값은 출력하지 마.

실제 토스 테스트 승인·조회·전체 취소, 실패·중복·결과 대조를 검증해.
수행하지 못한 시나리오는 미검증으로 남기고 가짜 PG 결과와 구분해.
테스트 사이트 주소·이미지 ID·검증 결과·남은 제한을 보고해.
실제 과금·live 키·판매자 실지급·운영 배포·원격 push는 범위에 포함하지 마.
```
