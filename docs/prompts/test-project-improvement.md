# Orca 전달용 테스트 프로젝트 개선 프롬프트

[작업 지시서](../test-project-improvement-work-plan.md)를 실행하기 위한 복사용 문안이다. 실제 구현과 검증은 Orca에서 진행한다.

## 전달 방법

1. Orca에서 현재 변경이 있는 `C:\work2\temp\socialapp` 폴더를 연다.
2. 같은 파일을 동시에 편집하는 다른 작업이 없는 상태에서 아래 프롬프트를 전달한다.
3. 새 체크아웃을 사용한다면 문서뿐 아니라 기존 미커밋 주문·결제·이미지 코드도 있는지 확인한다. 문서는 원격 `main`만을 기준으로 작성되지 않았다.

기본 권장은 먼저 1단계를 완결하고 결과를 확인한 뒤 다음 단계로 진행하는 방식이다. 전체 구현을 맡기려면 별도의 전체 실행 문안을 사용한다.

검증은 [AGENTS.md의 검증 기준](../../AGENTS.md#검증-기준)을 따른다. 작업 지시서의 단계별 검증은 관련 검사이며, 전체 필수 검증은 요청한 작업 범위의 최종 완료 시점에 모아서 수행한다. 다음 문안에는 이 원칙이 포함되어 있다.

## 처음 전달할 프롬프트 — 1단계

```text
현재 SummerGear 프로젝트의 테스트 사용성을 개선해줘.
실제 구현은 이 Orca 작업에서 진행해. SNS 로그인은 추후 작업이고 이번 범위에서 제외한다.

원본 작업 폴더는 C:\work2\temp\socialapp이다.
먼저 AGENTS.md와 docs/test-project-improvement-work-plan.md를 읽고,
현재 코드·관련 테스트·계약 문서를 대조해줘.
git status --short --branch, git worktree list, 최근 커밋을 확인하고
기존 미커밋 및 미추적 주문·결제·이미지 변경을 보존해줘.
원격 main만 가져온 새 체크아웃에는 필요한 코드가 빠져 있을 수 있으니 먼저 확인해줘.

이번 실행 범위는 작업 지시서의 1단계 전체다.
- 목록의 서버 오류·빈 목록·데모·데이터 출처 구분
- 등록·수정 후 목록 캐시 갱신과 재시도/로딩 처리
- 마이페이지에서 기존 주문 내역으로 진입하는 동선
- 테스트 결제 제공자와 처리 상태에 맞는 문구

분석이나 계획 제안에서 끝내지 말고 구현, 관련 회귀 검증, 검증 기록까지 완료해줘.
기존 동작을 문서와 다르다는 이유만으로 삭제하지 말고 의도와 소비자를 확인해줘.
작업 지시서의 완료 조건과 최신 AGENTS.md의 검증 범위·실행 횟수 기준을 적용해줘.
시작할 때 전체 테스트를 관례적으로 실행하지 말고 관련 수정을 묶어 진행해줘.
구현 중에는 영향받는 검사만, 전체 필수 검증은 1단계 완료 직전에 한 번 수행해줘.
통과한 검사는 이후 변경이 결과에 영향을 주거나 새 문제가 발견된 경우에만 재실행해줘.
실패하면 관련 검사부터 재실행하고, 상위 스크립트가 포함한 검사는 중복 실행하지 마.
성공 로그는 요약만, 실패 로그는 원인 주변부터 확인해줘.
브라우저 흐름도 확인하고 실제 API 연결 검사와 응답 모킹 검사를 구분해줘.

2~6단계 구현은 이번에 시작하지 말고, 연관된 발견 사항만 기록해줘.
외부 서비스 없이 가능한 작업은 계속하고 실제 키/서비스가 필요한 검증만 미완료로 표시해줘.
기존 미커밋·미추적 변경을 보존하고 임의 reset·stash로 작업 상태를 바꾸지 마.
필요한 로컬 브랜치 생성·전환과 워크트리 활용은 허용한다.
현재 미커밋 구현이 새 작업 공간에서 누락되지 않게 하고, 작은 작업에 불필요한 공간을 만들지 마.
사용량 절감을 위해 기본은 단일 에이전트로 진행해줘.
로컬 커밋은 이번 작업의 변경만 명시적으로 포함해도 된다.
같은 파일에 기존 변경이 섞여 있으면 diff를 구분해 기존 작업을 함께 커밋하지 마.
원격 push와 실제 배포는 별도로 요청할 때만 수행해줘.
완료 시 변경 파일·동작·계약 영향·검증 명령/결과·미검증 항목을 보고해줘.
```
